# U06 verification record (UCR-001 canonical resources)

## Scope and baseline

- Baseline: U01–U05 as implemented in this working tree. U06 makes
  `entity` the sole resource record: migration 0025 drops the legacy
  `resource` table and mirror triggers, backfills `resource_content_revision`
  and `subtype_locked`, rebuilds `resource_use` / `resource_tag` /
  `interviewer_candidate` foreign keys onto `entity`, and swaps the `graph_card`
  projection to entity. All resource consumers (board, materials, release,
  writing jobs, relations, parties, assistant, REST directory) were moved to
  canonical reads; `resource.get_summary`, `resource.create_draft` and
  `resource.mark_ready` commands are registered.
- Fixtures in `contract/fixtures/u06/commands/` are synthetic contract
  samples; no credentials or subject canaries are recorded.

## Implemented interfaces

- `migrations/0025_canonical_resources.sql`: content-revision split,
  subtype-lock, deterministic empty-subtype repair, divergent-mirror
  preflight, FK rebuilds, graph projection and legacy-table drop.
- `application/resources.rs`: `create_draft`, `mark_ready`, `summary`
  operations with typed errors and no-op semantics; `parley-domain/resources.rs`
  owns the pure subtype validator (a single gate for REST and commands).
- `resource_board.rs`: card edit/commit/retire/erase run entity-only; card
  and content revisions advance independently; affected material versions are
  flagged only on content-change or retirement.
- `lib.rs`: resource create/edit/read/directory adapters read the canonical
  row; resource REST etags keep their published format over the entity
  revision.
- `materials.rs` / `release.rs` / `writing.rs` / `writing_jobs.rs`:
  eligibility, dependency-vector and staleness gates use the canonical
  content revision.
- `commands/resource.rs` + `commands/read.rs`: create draft (P), mark ready
  (P) and summary (A1) descriptors, closed schemas, samples, audit
  allowlists and the `resource.read` / `resource.write` permissions.
- Frontend: one palette/editor; `resource_subtype` picker; the mark-ready
  front door freezes the selected card id and content revision; the mock and
  typed clients/decoders follow the canonical model (legacy `legacy` flag
  preserved as a published projection).

### Recovery and failure boundaries exercised

- upgrade of a pre-0025 workspace with legacy rows, mirrors, placements,
  material deps and deliveries → IDs/content revisions/delivery titles
  preserved, zero FK violations, legacy table gone;
- divergent populated mirrors abort the migration preflight;
- notes edits and board moves leave content proof intact; content edits bump
  content revision and flag dependents; retirement bumps content revision and
  recheck-required events;
- erase refusal via canonical reference FKs (delivered and material refs);
- command create/mark-ready/replay/idempotency-mismatch/stale-revision and
  concealed summary behaviour;
- agent run granted `resource.read` persists its target grant, reaches a
  terminal state and never exposes private fields.
