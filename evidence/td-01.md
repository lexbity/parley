## Harness (NFR-5)

`crates/parley-service/tests/support/delegated_probe.rs` is the reusable,
read-only probe. `dump(pool, run_id, entity)` returns:

- the `agent_run` row (state, revision, turns, tools, wake, wait, deadline);
- the `agent_run_budget` row (invocations, distinct intents, executed writes,
  destructive effects);
- paired `command_audit_event` attempt/outcome rows on `attempt_audit_id`;
- durable tool intents, jobs and job attempts;
- the committed transcript;
- the bounded `event` tail for the run's entity.

`dump_job(pool, job_id)` covers wakes that precede a run. `ProbeDump: Display`
lets an assertion attach the whole state as failure context without changing
what the assertion counts. The failing assertions in u03/u05/u07 carry the
dump in their messages, so a regression reproduces with one command.

`rg -n "todo|unimplemented|allow\\(dead_code\\)" tests/support/delegated_probe.rs`
returns zero hits; the module is registered from `tests/support/mod.rs`.

## Production fixes with named tests

1. `crates/parley-service/src/agent_runtime/mod.rs` — `canonical_history`
   synthesized a tool-result id that never matched the assistant `toolCall`
   id. Extracted the pure `canonical_rows` / `accepted_call_refs` projection
   and reused the recorded `call_ref`. Named unit test:
   `agent_runtime::tests::resumed_tool_result_reuses_the_accepted_call_ref`.
2. `agent/src/delegated.mjs` — resumed tool results were pushed with role
   `"tool"`; Pi Agent Core expects `"toolResult"` and inserted synthetic
   `"No result provided"` results. Named unit test:
   `resumed tool results keep their committed content and call id`.

Both defects affect real resumed delegated runs, not only fixtures.
