# R03 evidence — retirement, conflict resolution, cross-tab refresh

R03 completes the remaining lifecycle and concurrency behaviors:

- **Retirement**: `POST /resource-cards/{id}/retire` removes a card from
  ordinary use, the board and the picker, writes a `resource.retired` event,
  flags affected material versions for release recheck, and closes the door
  on later edits or new edges to the retired card. Reads and edits return
  404; edge creation to a retired endpoint is rejected.
- **Board-save edge preservation**: a board edit without a relationship
  intent never serializes or replaces the resource's edge collection — the
  connection count and dossier direct links stay intact.
- **Opportunity-board segregation**: resource moves only touch
  `resource_placement`; the Queue board snapshot is byte-identical before and
  after a resource move.
- **Three-way conflict resolution**: when a save hits 412 the editor shows
  Base / Yours / Current, offers "Keep my edits and retry" (adopt fresh
  revisions, keep the draft) and "Use current version" (reload the latest
  card).
- **Cross-tab refresh**: successful card saves/moves/retirements broadcast on
  a workspace `BroadcastChannel`; other tabs refresh without clobbering a
  live draft.
- **Keyboard activation**: Enter on the focused graph canvas opens the
  inspected resource in the editor (party nodes route to Parties).

Verified by `tests/r03.rs` (3 cases), the extended workspace component spec
(conflict retry + retire) and the mock e2e journey `r03.spec.ts`.
