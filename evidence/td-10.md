# TD-10 · Command-registry convergence — Wave 0, W1 step, SQL extraction

Evidence for the first TD-10 increment. Shape freeze is intact: no path,
payload, status code or wire expectation changed.

## Wave 0 — committed route inventory

- `ci/routes.py` parses every axum `.route("...")` registration in
  `crates/parley-service/src/**/*.rs`, extracts methods, and records path,
  method, defining module, dispatch class today, wave and exemption.
- `contract/fixtures/td10/route-inventory.json` is the committed artifact:
  **175 route/method entries** — 8 exempt, 167 non-exempt, 8 registry today;
  waves: 0=8 (registry), 1=12, 2=46, 3=101, exempt=8.
- Exempt classes are enumerated, not open-ended: SSE stream
  (`command-notifications`), one-time media bytes (`materials/{id}/download`),
  session/bootstrap/health, embedded UI (`/`, `/{tab}`, `/assets/*`).
- The gate is wired into `scripts/check-slice`, `.github/workflows/rust.yml`
  and `.github/workflows/web-mock.yml`.
- Negative control: injecting a planted route into the committed artifact
  makes `python3 ci/routes.py --check` exit 1 with "route inventory is stale";
  restoring the artifact makes it pass again.

## W1 step — table-driven dispatch

- `commands/http/pipeline.rs`: the historical if/else `Execution` chain is
  replaced by `EXECUTION_RESOLVERS: &[ExecutionResolver]` plus
  `resolve_execution(command_id)`. Reads and destructive commands keep their
  dedicated paths before the table; every write command is now added beside
  its owning module's descriptor table, not by growing a branch chain.
- `commands/policy.rs`: retired the stale `#[allow(dead_code)] // reserved for
  later slices` placeholders. `Effect::Read` and `Effect::Destructive` are
  live classifications used by descriptors and dispatch; the enum now states
  that contract in its doc comment.

## W2 — operation keys on legacy mutations (first cut)

- `materials.rs::create_opportunity` and `mark_resource_ready` no longer
  synthesize content-derived fallback digests (`rest-create\0title\0party`,
  `rest-ready\0id`). Both now require `Idempotency-Key` and include it in the
  operation digest; a missing key fails 400 `IDEMPOTENCY_KEY_REQUIRED`.
- `create_opportunity` now checks and stores an `idempotency_receipt` inside
  the writer transaction: same key replay returns the original record with no
  second effect, a different intent on the same key fails 409 `KEY_REUSED`.
  Wire shape and 201 status are unchanged.
- `client.ts::createOpportunity` now uses `mutate` with `newOperationKey()`;
  the e2e mock applies the same key/receipt rule to `POST /api/v1/opportunities`.
- `contract/fixtures/td10/admission/` pins the negative admission shapes:
  missing key (`malformed_request` on the registry transport,
  `IDEMPOTENCY_KEY_REQUIRED` on legacy), same-key replay receipt and
  `idempotency_mismatch`. All fixture bodies validate against the contract.
- `tests/td10_admission.rs` (4 tests) proves: both transports fail closed on a
  missing key; same-key board create yields one list and one receipt with the
  identical response; stale rename yields 412 `STALE_REVISION`; identical
  opportunity creates with distinct keys produce distinct effects and a replay
  of the first key returns the original record.
