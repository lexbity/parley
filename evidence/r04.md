# R04 evidence — party linking, stale-order guards, delivery drill-through

R04 completes the cross-entity provenance and order-conflict behavior:

- **Existing cross-tab party link**: linking a card to an existing party by
  party ID creates only the owner edge (e.g. "shared with") — no duplicate
  person or resource tile is created, and the party's canonical record (its
  dossier) shows the new direct link. The link survives subsequent board
  moves because it is stored on the edge table, independent of placement.
- **Stale-order rejection**: reorder/move commands carry expected placement
  and column revisions; a command built against a stale placement revision is
  rejected with 412 and never applied, so two-window reorders reconcile
  against refreshed order.
- **Delivery drill-through**: delivery rows now carry the material kind
  (outreach/followup/handoff) as a channel-like label and open the exact
  delivered material in Output, so an old send always resolves the material
  that was sent even after the resource is renamed or retired.
- **Epoch quarantine**: when a save fails with WORKSPACE_REPLACED the editor
  isolates the draft (copy out + discard), matching the app's rule that a
  draft must never be misapplied to a restored workspace.

Verified by `tests/r04.rs` (2 cases) plus the R02 delivery matrix and the
workspace component suite.
