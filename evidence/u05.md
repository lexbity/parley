# U05 verification record (UCR-001 brief.start / job.get_status)

## Scope and baseline

- Baseline: U01–U04 as implemented in this working tree. U05 adds the
  `brief.start` and `job.get_status` registry commands, the typed
  `application::brief` / `application::job_status` operations, the scoped
  durable-job columns and indexes (migration 0024), and the delegated
  run↔job wake/resume protocol with lease fencing.
- Fixtures in `contract/fixtures/u05/` are synthetic; no credentials, real
  names or subject canaries are recorded. This record is refreshed by
  `scripts/prove u05` on the committing revision.

## Implemented interfaces

- `application/brief.rs`: one transaction-scoped brief-start operation used
  by the command and the REST adapter; enqueue is committed with the run
  binding, scope and source revisions.
- `application/job_status.rs`: scoped job projection (progress, safe error,
  review reference) readable only under the originating grant.
- `commands/jobs.rs`: closed descriptors, schemas, samples and audit
  allowlists for `brief.start` (A2) and `job.get_status` (A2).
- `migrations/0024_scoped_command_jobs.sql`: `durable_job` gains epoch/run/
  owner-pseudonym binding and an indexed scoped-run lookup.
- `agent_runtime`: durable tool ordinals, wake-condition persistence and
  lease fencing; the provider lane is shared with fixed-role jobs.

### Recovery and failure boundaries exercised

- committed enqueue then process restart → same job id and one charge;
- worker claim with stale lease → second attempt can never publish a
  candidate (one eventual terminal outcome);
- lost wake signal → durable-queue poll recovers;
- cancelled run fences job completion at the writer;
- foreign-scope and foreign-job metadata lookups deny or conceal;
- backup snapshot scrubs scoped job and run payloads.
