# AR03 evidence — contextual Template Builder candidates and draft saves

## Slice exit criteria

- **General and contextual build requests share one typed start, one role
  and one validator.** `application/template_build.rs` owns the single
  `buildTemplates` admission and `run_builder` role execution; the manual
  form and the contextual selector pass through the same code path.
- **Candidate saves create exactly one immutable draft.** The integration
  test `ar03_candidate_save_is_one_version_and_fences_changes` seeds a
  succeeded builder job and a validated candidate, saves it once, replays the
  same idempotency key (same receipt, no second version), and proves a stale
  candidate revision is refused with `TEMPLATE_CANDIDATE_CLOSED`.
- **Party-specific text never becomes reusable skeleton text.** The test
  `ar03_candidate_save_rejects_party_specific_text` seeds a candidate whose
  frozen context names a real party and proves a save containing the party's
  literal name is rejected (`TEMPLATE_VALIDATION_FAILED`) by the shared
  canary rejection in `validate_variant`, while an identical valid skeleton
  saves cleanly.
- **Model unavailability preserves manual authoring.** `ar03_manual_template_draft_survives_model_unavailability`
  proves the packaged UI can create, approve and activate a template while
  the local model is unqualified; `ar03_contextual_build_admission_fails_closed_without_profile`
  proves contextual builds fail closed with `CAPABILITY_UNQUALIFIED` (503).
