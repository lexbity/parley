# U07 verification record (UCR-001 scoped writing grants)

## Scope and baseline

- Baseline: U01–U06 as implemented in this working tree. U07 registers
  `match.start`, `material.compose_draft` and `material.check_gate` as
  Tier-2 agent commands; extracts the matcher/composer job starts and the
  gate evaluation into typed application operations shared with the owner
  REST adapters; and fences delegated writing-job completion behind the
  initiating run and epoch.
- No new migration is needed: the durable job, agent-run and material
  schemas from U05/U06 are extended only by behaviour, not schema.
- Fixtures in `contract/fixtures/u07/commands/` are synthetic contract
  samples; no credentials or subject canaries are recorded.

## Implemented interfaces

- `application/match_start.rs`: typed `MatchStartInput/Result/Error`, the
  canonical ready-resource snapshot (filtered to a run's granted resource
  targets), matcher job enqueue inside the caller's transaction, and a
  `match.generation_queued` event. `application/compose_start.rs` is the
  composer counterpart with deterministic template/exchange/slot/shortlist
  validation and delegated resource-grant checks. `application/material_gate.rs`
  evaluates the content gates and projects bounded codes, severities and a
  summary only.
- `commands/writing.rs`: closed descriptors, wire args, serde/schema
  agreement, samples and audit allowlists for the three commands. The gate
  command executes through the shared read pipeline (`commands/read.rs`).
- `commands/policy.rs`: `match.start`, `material.compose`, `material.gate`
  permissions added to the closed permission set.
- `commands/http.rs`: registry execution and error mapping for the writing
  commands; concealed-target and stale-revision responses match the §4.1
  contract.
- `writing.rs` REST adapters: `start_match` and `compose_material` now share
  the application operations; published owner wire DTOs, status codes and
  error codes are preserved. `save_composer_candidate` converts the worker's
  sentence-claim audit into typed owner-review bindings so the gate and
  release checks can evaluate candidates.
- `writing_jobs.rs`: delegated job completion is fenced by the initiating run
  and epoch in addition to scope revisions.
- `agent_runtime/tools.rs`: job-start command detection now parks runs on
  match/compose jobs exactly like brief jobs.
- Frontend: `DelegatedRuns.vue` opens an opportunity-scoped review on the
  Output workspace; `RUN_PERMISSIONS` includes the three writing grants; the
  mock implements the three commands and its writing-run state machine.

### Recovery and failure boundaries exercised

- scoped end-to-end match → compose → wait/job review → owner save → gate
  check → approve → release with exactly two executed writes and one match
  run whose shortlist contains only granted resources;
- hidden resources and foreign opportunities never reach a scoped run; the
  same public denial is returned by the agent tool path;
- a resource content revision changed while a composer job is in flight
  fences completion: zero material installed, candidate bytes preserved only
  in the attempt output;
- malformed provider output remains plain data: the job fails through the
  registry ledger and no material is installed;
- stale compose preconditions (slots, template, exchange) deny with zero
  effects and typed errors;
- gate targets are concealed and version-bound; a missing material is
  indistinguishably denied and a terminal receipt is written;
- boot validation still rejects malformed writing registrations, and owner
  palette/describe surfaces never reveal agent-only commands (verified in
  both Playwright projects against the real service).
