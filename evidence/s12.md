## Failing gates and cause

- Before the repair, `ci/contract.py --through s12 --check-generated` and
  `ci/trace.py --through s12 --check-manifest` failed because s12 had zero
  coverage rows, no fixture directory and no evidence artifact. Rows,
  fixtures and this record were added.
- `ci/migrations.py --through s12` previously applied only 17 prefixes: its
  `required` list omitted r01–r04/s12, so 0018/0019/0020 were never applied
  or checksummed, and prefixes were sliced in slice order rather than numeric
  order. The gate now derives ownership from all slices through the requested
  ID and selects files by numeric prefix.
- `scripts/prove s12` previously mapped to the non-existent `tests/s12.rs`.
  The mapping now comes from `ci/trace.py::rust_test_target` (`s12_queue_sheet`).
- During regeneration, the first attempt used
  `pnpm --dir web exec openapi-typescript ../contract/openapi.yaml -o web/src/api/generated.ts`
  from the repo root. `pnpm --dir web` runs the command with cwd `web/`, so
  that wrote `web/web/src/api/generated.ts` and left the real generated file
  stale; `ci/contract.py --check-generated` correctly failed. The stray
  directory was removed and the file regenerated with
  `pnpm --dir web exec openapi-typescript ../contract/openapi.yaml -o src/api/generated.ts`;
  the gate then passed byte-for-byte.
- `scripts/prove s12` was initially blocked because `web/e2e/s12.spec.ts` and
  the s12 coverage rows did not exist. Both were added; the proof runner now
  completes with positive counts in both projects and trace matched every ID.
- Intermediate `ci/coverage.py --check --rust` failures were caused by the
  concurrently written U01 suite; after its compile and ledger/descriptor
  fixes the final gate passed at 18.68/92.70/67.17% (see the table).
