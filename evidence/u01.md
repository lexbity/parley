## Recovery boundary

What is proven here: the ledger migration applies and checksums in numeric
order; the contract and generated client cover the command envelope, replay
fields and error details; the coverage manifest maps every named test ID to a
fixture and this evidence; the ownership gate fails when 0019 or 0020 loses
its owner.

Contract/implementation note: the OpenAPI command responses advertise
`Cache-Control: private, no-store`; `private_headers` was aligned to that
exact value and `u01_manifest_search_describe_contract` asserts the live
response header byte-for-byte.

U02 follow-on note: the command table policy map version is now 2 (the
U01 assertion is deliberately relaxed to `>= 1` so it stays valid), and
`command_audit_event` was rebuilt by `0022_agent_runs.sql` to extend
`actor_kind` with the pseudonymous `agent` actor. U01's owner results above
are unchanged; U02 evidence records the new table policy and audit proof.

The committed-effect boundary is now executed, not merely described:
`u01_precommit_crash_leaves_no_effect` proves the savepoint rollback leaves
zero facts and zero receipts and that the same key can still commit;
`u01_postcommit_crash_replays_committed_effect` proves an ambiguous 503 after
commit replays the exact stored event and result under the same key;
`u01_replay_after_lost_ack_restores_original_result` proves the same after a
client disconnect; `u01_startup_recovery_finalizes_interrupted_attempt`
proves an orphan attempt is finalized as `interrupted` on reopen; and
`u01_audit_unavailable_fails_closed` proves an unavailable audit store blocks
all effects. `u01_set_phase_single_effect_under_32_concurrent_same_key`
establishes exactly one mutation, one event and one receipt with 31 separate
replay outcomes for 32 identical admitted attempts.

Not claimed in U01: delegated agent authority, approval state machines,
job/provider continuations, remote agents, epoch replacement under concurrent
command load (the generation fence is wired and unit-checked but no full
restore-during-write test runs in this slice). Those belong to U02–U09.

## Failing gates and cause

- `ci/contract.py --through u01 --check-generated` initially failed because
  u01 (and s12, r01–r04) had zero coverage rows. Rows, fixtures and evidence
  were added. A second failure was caused by regenerating with
  `-o web/src/api/generated.ts` under `pnpm --dir web`, which writes relative
  to `web/` and produced `web/web/src/api/generated.ts`; the stray directory
  was removed and the correct relative output path used (see above).
- `ci/migrations.py --through u01` previously required only s01–s11 slices,
  omitting r01–r04/s12 and their 0018/0019/0020 migrations, and sliced
  prefixes by slice order. It now builds `required` from all slices through
  the requested ID, applies files by numeric prefix, verifies unique
  ownership and runs the negative self-test.
- `ci/trace.py --through u01 --check-manifest` initially failed for the same
  zero-row reason; it now passes. `--slice s12 --require-executed` initially
  looked for `tests/s12.rs`; it now maps to `tests/s12_queue_sheet.rs`.
- `scripts/prove` rejected `u01` with a hardcoded regex; it now derives the
  accepted set from `ci/common.py::SLICE_ORDER` and derives the cargo target
  from `ci/trace.py::rust_test_target`.
- `scripts/prove u01` and `scripts/prove s12` were initially blocked because
  the U01 Rust/Playwright suites and the s12 coverage rows did not exist.
  Both were added and both proof runners now complete with positive counts in
  every project, as recorded above.
- A late `python3 -B ci/disk.py --check` failed because concurrent Cargo and
  coverage builds pushed `target/` to 12.2 GiB, above the 12 GiB fail budget.
  `cargo llvm-cov clean` removed the regenerable 7.3 GiB coverage cache
  (`target/llvm-cov-target`); the gate then passed at 4.8 GiB.
- While the U01 suite was being written, `ci/coverage.py --check --rust`
  failed on compile errors in the new test (then on ordering/type mistakes in
  the ledger and descriptor code that the tests exposed). All were corrected:
  the ledger now stores `response_status` and `response_variant`, terminal
  outcomes use the right column counts and integer types, context expressions
  distinguish quoted literals from keys, and undo keeps the current stage as
  its event predecessor. A final `ci/coverage.py --check --rust` passed at
  cli 18.68%, domain 92.70%, service 67.17% against floors 18/90/60.
- `s10_queue_5000_parties_meets_render_budget` failed intermittently while
  other Cargo/coverage builds were running (the same failure reproduces at
  the unmodified baseline commit `102afed` under that load). A final
  `cargo test --locked --workspace` with no competing builds passed all
  suites, including s10, so no floor or budget was relaxed.
