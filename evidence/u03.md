# U03 verification record (UCR-001 delegated opportunity creation)

## Scope and baseline

- Baseline: U01 and U02 as implemented in this working tree. U03 adds
  `opportunity.create`, the shared typed create operation, self-created target
  binding, executed-effect budgeting and the owner palette / delegation
  consent surfaces. No new migration is owned by U03: the created target is
  bound as an `agent_run_target` row in the same operation transaction, and
  the effect counters already exist in `0022_agent_runs.sql`.
- Fixtures in `contract/fixtures/u03/commands/` are synthetic: no real names,
  session tokens, credentials or subject canaries.

## Implemented interfaces

- `application/opportunity.rs`: one transaction-scoped create operation with
  typed input, result and errors; allocates the ID, checks the active primary
  party, creates the board placement and party policy, emits both creation
  events with their cursor, and optionally binds the created opportunity to a
  delegated run.
- `commands/opportunity.rs`: the closed `opportunity.create` descriptor,
  schemas, sample args and positive audit allowlist.
- `commands/http.rs`: one closed-schema gate for every command (including
  reads), a write-effect allowance checked only after replay is ruled out,
  per-run invocation windows, and audit of every admitted attempt.
- `materials.rs`: the REST create route now submits the same typed operation
  through the bounded writer and projects the published DTO inside the same
  transaction; the post-commit fetch and the duplicate create path are gone.

## Recovery boundary

- `u03_create_crash_boundaries_and_key_discipline` proves a pre-commit crash
  leaves zero facts and the same key can still commit, while an ambiguous
  post-commit result replays exactly one committed effect. A different intent
  on the same key is terminal.
- `u03_concurrent_same_key_creates_produce_one_effect` proves 32 identical
  admitted attempts produce one opportunity, one creation event, one receipt
  and 32 separate terminal audit outcomes.
- `u03_agent_create_binds_self_created_target_and_advances_phase` proves the
  created target is inserted into the run scope in the create transaction and
  that create and phase each debit one executed write.
- `u03_revocation_fences_phase_tool_and_replay` proves cancellation wins at
  the writer over a delayed provider result, leaving zero effects and zero
  receipts for the fenced tool call.
- `u03_executed_write_allowance_is_debited_once_per_effect` proves the tenth
  effect commits, the eleventh is refused with `budget_exceeded`, and the
  counter is 10 after reopen. Replay is authorized before the effect
  allowance check, so an authorized replay of an earlier intent cannot be
  denied by a later exhausted allowance.
- `u03_restart_preserves_created_facts_audit_and_budgets` proves the created
  fact, its event, the audit outcome pair and the budget survive reopen.
- `u03_noop_phase_consumes_zero_executed_write_allowance` proves a same-stage
  phase command returns current permitted state and emits zero events while
  consuming zero executed-write allowance (FR-2), while still recording one
  admitted invocation, its terminal audit outcome and a replayable receipt.
