# U08 verification record (UCR-001 destructive registry retirement with approval)

## Scope and baseline

- Baseline: U01–U07 landed; command registry, ledger, agent runtime and the
  canonical resource operation exist. This slice adds the first destructive
  command (`resource.retire`), the owner approval store, the shared retirement
  application operation, and the SSS notification stream.
- Migration `0026_command_approvals.sql` introduces `command_approval`
  (approval rows with binding, TTL and terminal purge), `approval_bytes`
  metering on `command_ledger_meta`, and `args_json` on
  `agent_tool_intent` for durable intent resume. Owned by u08.
- The owner REST retirement route (`POST /resource-cards/{id}/retire`) keeps
  its direct, owner-authenticated entry and wire envelope but now executes the
  same application operation as the registry command (UCR-001 §5.3).
- Fixtures in `contract/fixtures/u08/commands/` are synthetic contract samples;
  no credentials or subject canaries are recorded.

## Implemented interfaces

- `application/resource_retirement.rs` — typed retirement operation and the
  read-only planner: card/content revisions, placement state, ordered distinct
  material-version dependency vector, bounded 256-version scan, capped preview
  sample, and the deterministic dependency fingerprint (Q5 / §5.3).
- `commands/approval.rs` — approval store: pending/granted/consumed/denied/
  revoked/expired/stale lifecycle, decision idempotency, TTL sweep, payload
  purge and quotas.
- `commands/resource.rs` — `resource.retire` descriptor (destructive; palette +
  agent tier 2; dry run with preview schema; typed args sample agreement).
- `commands/http.rs` — owner `/approvals` list/detail/grant/deny, `Location`
  header for `approval_required`, the destructive pipeline (plan → pending →
  grant → reservation-time fingerprint recheck → consume+effect in one
  savepoint), and the fetch-based SSE `/command-notifications` stream with a
  bounded connection count and heartbeat.
- `commands/policy.rs`, `commands/descriptor.rs` — `resource.retire`
  permission; `preview_schema` descriptor field with boot validation.
- `agent_runtime/{tools,turn,mod,http}.rs` — deterministic tool intent keys,
  durable intent args, `waiting_owner` parking and resume, and `run_changed`
  notifications.
- `maintenance.rs` — `command_approval` added to the versioned scrub/export
  table policy (version 4).
- Frontend: `command.ts` approval client + notification stream, `registry.ts`
  `resourceRetireAction`, `CommandPalette.vue` approval-pending step with
  frozen intent resume, `ApprovalInbox.vue` owner inbox, and
  `ResourcesWorkspace.vue` refresh after retirement.

## Recovery and failure boundaries exercised

- First destructive request records a pending approval, returns 403
  `approval_required` with the owner-only `Location`, and repeats the same
  location for the same pending intent.
- 32 concurrent same-key callers after grant produce one mutation, one
  `resource.retired` event, one executed receipt and 31 replays.
- Deny fails closed; decisions replay exactly on the same decision key and
  conflict on a changed revision; a deny at the current revision revokes a
  granted approval.
- A dependency change between grant and execution turns the approval stale
  (409 `approval_stale`, zero effect) and purges private payloads.
- Dry run returns the observational preview with a dry-run receipt and zero
  domain effects or approvals.
- Expired pending/granted approvals fail closed.
- >256 impacted material versions use the owner workflow (409
  `requires_owner_workflow`).
- Pre-commit crash after claim aborts the transaction; the grant remains
  usable on the original key and the retry commits exactly once.
- Owner REST retirement still replays by its own receipts and shares the
  application facts.
- A delegated agent run parks on `waiting_owner`, hides the approval id from
  the model, resumes after grant via its durable tool intent, and commits the
  effect; owner inbox lists run approvals.
- The SSE stream emits `epoch_changed` on open and `approvals_changed` after a
  pending approval is recorded.
