# R01 evidence — resource board

Slice R01 lands the first delivery increment of the Resources amendment
(2026-11-22): an editable board seeded with Inbox, Developing and Available, stable board/graph/inspector selection,
the shared content editor with explicit Save card, atomic card commits and
moves, owner-authored edges, entity attachment bindings, and the delivery
projection from sent material versions. Legacy resources stay off board and
discoverable through the picker.

## What shipped

- Migration `0018_resource_board.sql`: entity subtype/body/readiness columns,
  owner-edge basis/author columns, `resource_column` (seeded Inbox/Developing/
  Available) and `resource_placement` with guards and order index.
- Backend (`crates/parley-service/src/resource_board.rs`):
  - `GET /api/v1/resource-board` — ordered columns, paged card summaries with
    file/connection/delivery counts, off-board picker union (including legacy
    resources), event fence.
  - `GET /api/v1/resource-cards/{id}` — full card read for the editor.
  - `POST /api/v1/resource-card-commits` — atomic create/edit + placement +
    attachment bind/unbind + graph-only relationship intents in one writer
    transaction with idempotency receipts.
  - `POST /api/v1/resource-board/columns` appends a list. `DELETE /api/v1/resource-board/columns/{id}` checks the list revision and moves its cards off board in one transaction.
  - `POST /api/v1/resource-board/moves` — move/reorder/remove with expected
    revisions and rank rebalancing.
  - `POST /edges`, `PATCH/DELETE /edges/{id}` — owner-authored edges with
    basis, correction and detach (both endpoints preserved).
  - `/api/v1/entities/{id}/attachments[/{reference}[/content]]` — bind,
    unbind, list and owner-content read of staged uploads.
  - Session capabilities `resource.board|resource.attachments|resource.relationships`.
- Contract: OpenAPI operations and schemas above; regenerated client.
- Frontend: `ResourcesWorkspace.vue` (board, graph, inspector, picker,
  breakpoint views) and `ResourceEditorForm.vue` (shared editor with typed
  fields, Markdown preview, file staging UI, placement, relationship intent,
  conflict handling). Old ResourceEditor surface replaced in the Resources tab.
- Mock parity in `web/e2e/mock-api.ts`; Playwright journey `r01.spec.ts`;
  Rust integration `tests/r01.rs`; Vitest workspace spec.

## Acceptance highlights

| Scenario | Observation |
|---|---|
| Add from column | Commit creates one entity + placement; board shows one card with identical notes; cancel creates nothing. |
| Select vs Edit | Tile sets graph root and inspector; board Edit opens the shared form; saving never creates/deletes relationships. |
| Rename + remove file, cancel | Edit from board renames; reopening keeps notes; removal marked then Cancel restores. |
| Off-board child | Related Artifact created from graph node is off board; edge exists in semantic list; picker finds it. |
| Relationship removal | A related card offers removal of a single link. When two links exist, the selector removes the chosen link and preserves both cards. |
| Remove a list | The list disappears and its cards remain available in the resource picker. |
| Stale/atomic | 412 on stale entity/notes revisions; same operation key replays the same card. |
| Delivery distinction | Only a sent material version contributes to the delivery count; drafting-only dependency does not. |
| Empty board | Columns, Add cards and the picker remain available; first entry selects the first card in order. |
| Accessible recovery | All graph actions have named semantic-list equivalents; keyboard Enter opens a node editor; narrow breakpoint keeps selection and drafts. |

## Board controls amendment (2026-11-23)

List management became fully owner-facing and WYSIWYG:

- **List rename**: `PATCH /resource-board/columns/{id}` (`renameResourceColumn`)
  renames in place under the column revision guard, receipts replays and emits
  `resource_column.renamed`. The board header edits the title directly.
- **Column kind**: `ResourceColumn` now carries `kind` (`owner`/`system`).
  Migration `0023_resource_board_controls.sql` demotes the seeded Developing
  and Available lists to owner lists; Inbox stays `system` and removal asks
  for a typed extra confirmation because the seed never recreates it.
- **Card revision on summaries**: `ResourceCardSummary.revision` exposes the
  entity revision so tiles can guard in-place title edits.
- **WYSIWYG board**: an always-visible title input at the bottom of every list
  adds cards inline; empty lists collapse into vertical pills; the lane `…`
  menu hosts Rename/Remove; tile titles edit in place.
