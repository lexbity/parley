# AR06 evidence — Extractor through the typed role port

## Slice exit criteria

- **Capture is independent of inference.** `application/extract.rs` is the
  single typed admission. The source save always commits atomically with the
  idempotency receipt; a durable Extractor job is admitted only when an active
  qualified structured profile exists, the queue has capacity and the whole
  chunk plan fits the pinned context budget. Without a qualified profile the
  capture returns `job_status: "not_queued"` and stays fully usable for
  manual review.
- **One bounded attempt, one preplanned chunk set.** The chunk plan is frozen
  at admission from sanitized byte offsets with exact budget/overlap (max 16
  chunks). The same deterministic slicing is re-applied at execution, so the
  worker only ever sees bounded, pre-reserved input. No `length-as-token`
  placeholder remains.
- **Every chunk runs as its own bounded worker execution under one durable
  lease.** `inference/extractor.rs` claims the lease once and runs the plan
  serially through the packaged Pi worker (real bundle, UDS relay, closed
  codec). A failed chunk invalidates the whole candidate batch; no partial
  candidate set is ever published.
- **Host-side deterministic validation stays authoritative.** Schema caps,
  sensitive-content rejection, exact quote verification against the original
  bytes and cross-chunk deduplication all run in Rust. The model's text is
  data.
- **Direct Extractor provider client removed.** The legacy extractor branch in
  `jobs.rs`, its native `ollama_chat` chunk loop and its helpers
  (`chunks`, `valid_candidate`, `save_proposals`, …) are deleted; the role
  dispatches exclusively through the inference port.
- **Existing S04 gates replay on the real wire.** The RFC-0001 Extractor
  staging/cancellation/retry/health assertions were migrated from the obsolete
  native fixture to the scripted Ollama-compatible SSE upstream and the same
  packaged worker, preserving every original assertion.

## Results (reference host, this checkout)

- `ar06_chunk_budget_and_original_span_round_trip` — pass. A 5 KB capture ran
  as multiple real worker executions (verified via recorded upstream chat
  calls). Proposals staged with byte-exact original spans, canonical
  normalization version, and a duplicated quote from one chunk collapsed to a
  single staged proposal.
- `ar06_cancel_or_bad_chunk_leaves_saved_source_only` — pass. Cancelling while
  the second chunk was held left zero proposal batches; the occurrence row
  remains retrievable.
- `ar06_bad_chunk_invalidates_the_candidate_batch` — pass. Three
  `RESULT_INVALID` outputs exhaust the attempt budget to `invalid`; no batch
  is created.
- `ar06_identical_source_keeps_independent_scope_edges` — pass. Two captures of
  the same text keep two occurrences, two jobs and two batches; reviewing one
  leaves the other pending with its own provenance.
- `ar06_capture_admission_is_atomic_and_typed` — pass. Concurrent same-key
  captures commit exactly one occurrence, one receipt and one job; the writer
  re-checks the receipt under its reservation.
- RFC-0001 S04 (all 5) — pass on the scripted SSE wire. Includes staging +
  selected-review closure, source survival without a model, late-result fence
  under cancellation, retry budget and provider health digest events.
- `s04_capture_remains_saved_when_provider_is_unavailable` now asserts the
  typed `not_queued` outcome rather than an invented failed job.

## Browser proof

`web/e2e/ar06.spec.ts` covers capture → review → reload on the mock project
and fail-closed source-only behavior on the Rust project (no qualified local
pairing is provisioned in the browser lane). PartyDesk no longer owns a
view-local `pollExtractor` loop; it uses the shared session-owned
`observeRoleJob` reconciler and reads the staged batch once at terminal.

`scripts/prove ar06` ran in this checkout and completed green: cargo 5/5
(`ar06` integration suite), Playwright 4 expected results matched on the mock
and rust projects (the rust project builds the real release binary), and
`ci/trace.py --require-executed` matched every coverage ID with positive
executed counts.
