# TD01 · Delegated-run proof debt (u03 / u05 / u07)

Slice 2026-11-24 · branch `merger` · TD-001 part 2 · closes FR-1 and NFR-5.

## Goal

Make the six failing delegated-run tests pass without deleting, renaming or
weakening an assertion, by classifying each failure against instrumented
durable state before changing anything. A production regression must be fixed
in production with a named unit test; a fixture drift must be repaired while
preserving the counted semantics.

## Baseline (verified before any fix)

`cargo test --locked -p parley-service --test u03 --test u05 --test u07`:

- u03: 7 passed / 3 failed
- u05: 5 passed / 2 failed
- u07: 6 passed / 1 failed

That is six failing tests, not ten (the spec's "ten failing tests" counts the
ten tests in u03). u05's failed run matched the spec's signature exactly:
`state=failed`, `wake_condition=PROVIDER_FAILED`, `turn_count=35`.

## Harness (NFR-5)

`crates/parley-service/tests/support/delegated_probe.rs` (new) is a reusable,
read-only probe. `dump(pool, run_id, entity)` returns the run row, the budget
row, paired `command_audit_event` attempt/outcome rows, durable tool intents,
jobs and attempts, the committed transcript, and a bounded event tail.
`dump_job(pool, job_id)` is the job-side view for wakes that precede a run.
`ProbeDump: Display` lets an assertion attach the whole durable state as
failure context. No `todo`, `unimplemented` or `allow(dead_code)` appears in
the file; it is registered from `tests/support/mod.rs` and is available to
every integration suite that declares `mod support;`.

The failing assertions in u03/u05/u07 now carry this dump in their messages,
so a future regression reproduces with one command.

The spec's first suspected causes were checked and rejected by the probe: the
debit path in `commands/http.rs` is shared with owners and increments once per
committed effect, and the dispatcher does wake and claim jobs. The u05
suspicion about turn reconstruction was partly right: the committed turns were
present in the database, but two host/worker reconstruction defects made the
worker discard them on resume.

## Production fixes (with named tests)

1. `crates/parley-service/src/agent_runtime/mod.rs` — `canonical_history`
   synthesized `tool-{run}-{turn}-{ordinal}` as the tool-result id, which
   never matched the assistant `toolCall` id recorded by `accept_turn`.
   Extracted the pure `canonical_rows` / `accepted_call_refs` projection and
   reused the recorded `call_ref`. Named unit test:
   `agent_runtime::tests::resumed_tool_result_reuses_the_accepted_call_ref`.
2. `agent/src/delegated.mjs` — `canonicalMessages` pushed resumed tool results
   with role `"tool"`; Pi Agent Core expects `"toolResult"` and therefore
   inserted synthetic `"No result provided"` results for the orphaned calls.
   Named unit test: `resumed tool results keep their committed content and
   call id` in `agent/test/delegated.test.mjs`.

Both defects affect real resumed delegated runs, not just fixtures.

## Other changes
